# 安卓界面重设计 · v1.6.0

依据用户提供的《stand up Android UI 重设计报告》（2026-11-19）执行，目标手机 Redmi K70 Pro / Android 16；继续支持 Android 8.0+。

## 实现范围

采用报告的原生 View + UI state 方案：绿色主色 `#287C70`、浅绿色 `#E8F3F0`、背景 `#F4F6F8`、正文 `#18212B`、次级文字 `#667382`、提醒底色 `#F4EEE4`。一个首页、音乐底部面板、休息页、按需权限页；不添加底部导航。系统字体与统一自带矢量图标，触摸区域至少 48dp。

首页保留计时卡和音乐摘要；权限正常时不展示说明卡。每个状态只有一个主要动作：

| 状态 | 主动作 | 其他动作 |
| --- | --- | --- |
| IDLE | 开始专注 | 15/30/45/60 分钟、自定义 1–999 分钟 |
| RUNNING | 暂停计时 | 结束本轮、调整时长；改变当前轮之前确认 |
| PAUSED | 继续专注 | 重新开始（确认）、调整下次时长；继续保留剩余时间 |
| DUE | 知道了 | 确认回到待开始，不自动计时或恢复音乐 |

运行中调整时长：输入与确认阶段不影响旧计时；确认后重新开始所选时长。暂停时调整时长仅更新下次使用的选择；继续仍使用当前剩余时间，“重新开始”才使用新时长。选择值保存到本地，旋转和进程重建后保留。

音乐面板提供上一首/播放暂停/下一首、进度、三种播放方式、导入和移除；首页只显示歌曲与播放暂停。失败时标识具体曲目并提供重选/移除操作。用户取消文件选择器或弹窗不改变当前计时和播放。

首次开始且缺权限时说明用途，并允许“先开始计时”；不连续弹系统授权框。权限页分别提供通知和准确提醒系统入口；回来重查。频道关闭需识别；静音频道说明不夸大声音能力。重启提示可关闭且关闭后不重复。

保留 TimerState/TimerRepository/AlarmScheduler 的时间算法、持久化与旧闹钟代次校验，保留 Media3 服务、音频焦点与文件选择器。通知确认与应用内确认都结束到时状态；旧通知确认不能误重置新计时。

## 实施顺序与验收

1. **状态层**：增加可独立测试的 TimerUiState 映射；覆盖四种状态、主次按钮、边界分钟、暂停后继续和调整行为。先失败测试，后实现。
2. **主屏**：独立 TimerScreen/TimerCard/DurationSelector/MusicSummary 组件；确认弹窗、时长校验、状态恢复。
3. **音乐面板**：保留 MediaController，加入曲目错误恢复与无障碍进度操作。
4. **休息与权限页**：明确 DUE 页面、确认行为、按需权限提示、一次性重启说明。
5. **适配与交付**：单元测试、lint、Android 16 模拟器回归、1.0/1.3/1.5 倍字体、窄屏/横屏、系统栏和可访问性节点检查；真机可听效果、厂商省电策略和 TalkBack 实际语音反馈不以模拟器替代。

## 文件与发布

主要修改 `android/app/src/main/java/com/zhaopw/standup/`、资源和安卓测试；按职责拆分，不引入 Compose。应用版本 1.6.0 / 16000，沿用原发布密钥以便覆盖安装。

用户原有桌面修改保持原样且不混入提交。通过已提交版本的发布流程验证 Windows x64、macOS arm64、macOS x86_64、Linux 和 Android，同版本统一发布。保留 Mac 试用与未公证说明。成品放根目录 `dist/`，版本归档放 `archive/releases/v1.6.0/`。
